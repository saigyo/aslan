Reports a field name, or $, that a JSONata expression would look up in the input of the expression itself, and every $$. Step Functions evaluates its expressions without such an input and rejects the definition when it is created; the state's input is $states.input.

Names on the right side of a path, in a filter predicate, in a group-by or order-by, and in a transform are evaluated against the values of the path and are not reported, as in $states.input.items[price > 1].name. AWS was shown to reject such names at the top level, in brackets, in array and object constructors, as an argument, in a function body, as an operand and as the first step of a path; the check applies the same rule to the other places that inherit the missing input in JSONata. Where it cannot judge with certainty, such as the right side of ~>, a focus or index binding, a function passed to a function of your own, or an expression that binds $ or $$ itself, it stays silent. The wildcards * and ** and the parent operator % are not reported.

An expression that contains a deployment-time placeholder such as ${Name} outside a string literal is not checked. To switch the check off, disable this inspection in Settings | Editor | Inspections | Amazon States Language.
